# ValueBet Engine — спецификация

Этот файл лежит в корне репозитория. Он единственный источник правды по решениям проекта.
Исполнитель (zcode) и ревьюер (Claude Code) читают его перед каждой фазой.
Любое отклонение от спецификации нужно явно отметить в `docs/decisions.md` с причиной.

## 1. Цель

Сервис ищет **value bets** на футбольные матчи. Value — ситуация, где вероятность исхода по модели
выше вероятности, заложенной в коэффициент букмекера: `edge = p_model * odds - 1 > порог`.

Бот **не** угадывает победителя (рынок 1X2 не используется) и **не** ставит автоматически.
Он рекомендует, логирует и честно считает свою статистику.

### Рынки
- **Точный счёт** (одна ячейка матрицы счетов).
- **Мультисчёт** в двух формах: набор счетов (`{1:0, 2:0, 2:1}`) и диапазон суммы голов (`2–4 гола`).
- **Тоталы** больше/меньше: 0.5, 1.5, 2.5, 3.5, 4.5 (матч целиком).
- **Обе забьют** (да/нет) как бесплатный побочный рынок.

### Покрытие
- Топ-5 лиг: Premier League, La Liga, Serie A, Bundesliga, Ligue 1.
- Лига чемпионов: **только тоталы**, отдельный флаг `experimental` (фаза 11).

## 2. Ключевой принцип

**Все вероятности считает статистическая модель. LLM никогда не задаёт числа в основном контуре.**
LLM только: (а) извлекает факты из новостей в JSON, (б) пишет текстовое обоснование,
(в) в теневом режиме предлагает поправку, которая логируется, но пользователю не показывается.

## 3. Данные (всё бесплатное, кроме Gemini)

| Что | Источник | Примечание |
|---|---|---|
| История результатов + закрывающие коэффициенты O/U 2.5 | football-data.co.uk (CSV) | для обучения и бэктеста |
| xG по матчам | Understat через `soccerdata` (или аналог) | неофициально; кэшировать, не долбить |
| Расписание, результаты, составы, травмы | API-Football, бесплатный тариф | жёсткий дневной лимит → учёт квоты + кэш |
| Коэффициенты на тоталы | odds-API с бесплатным тарифом (напр. The Odds API) | выбор по итогам фазы 0 |
| Коэффициенты на точный счёт / мультисчёт | **ручной ввод** пользователем | через Hermes или форму дашборда |
| Новости о составах | поисковый API с бесплатной квотой (напр. Tavily) | только для матчей-кандидатов |
| LLM | Gemini API (платный), через абстракцию провайдера | модели задаются в конфиге |

Конкретные лимиты бесплатных тарифов не захардкожены в спецификации: их проверяет фаза 0
и записывает в `docs/data-sources.md`.

## 4. Модель

- **Dixon-Coles** отдельно для каждой лиги: параметры атаки и обороны для каждой команды,
  преимущество своего поля для каждой лиги, коррекция `rho` для низких счетов.
- **Затухание по времени**: вес матча `exp(-xi * дни_назад)`, `xi` подбирается в бэктесте.
- **Смесь голов и xG**: квази-пуассоновское правдоподобие на `w * goals + (1 - w) * xG`,
  `w` подбирается в бэктесте.
- Выход: матрица вероятностей счетов 0..10 × 0..10 (остаток хвоста нормировать).
- Все рынки выводятся из матрицы чистыми функциями.
- Обучение строго на матчах **до** даты прогноза (никакой утечки будущего).

## 5. Отбор value

- `edge = p_model * odds - 1`.
- Пороги по рынкам (в конфиге, стартовые значения):
  - тоталы: edge ≥ 4%;
  - мультисчёт: edge ≥ 8%;
  - точный счёт: edge ≥ 12%, `p_model ≥ 4%`, коэффициент ≤ 21.
- Для тоталов из API берётся лучший доступный коэффициент среди букмекеров; рядом показывается
  вероятность рынка без маржи (de-vig) для контекста.
- Ручной ввод: парсер свободного текста вида `2:1 @ 8.5, 1:1 @ 6.0, ТБ 2.5 @ 1.95, 2-4 гола @ 1.80`.

## 6. Составы и флаг риска ⚠️

- **Ключевой игрок** — входил в старт в ≥ 70% из последних 8 матчей команды (параметры в конфиге).
- Источники отсутствий: API-Football (травмы/дисквалификации) + LLM-извлечение из новостей.
- LLM возвращает строгий JSON: `[{player, team, status: out|doubtful|suspended, source_url, quote_summary}]`.
- Правила флага:
  - отсутствует ключевой игрок или источники противоречат друг другу → ⚠️, порог edge × 1.5;
  - отсутствуют ≥ 2 ключевых игрока одной команды → ставка исключается.
- **Теневой режим**: LLM предлагает множители к атаке/обороне; модель пересчитывается с ними;
  результат логируется как `variant=shadow_llm`, пользователю не показывается.
- Поиск новостей запускается только для кандидатов в value: за T-24ч и T-2ч до матча.

## 7. Ставки и трекинг

- Для оценки качества каждая рекомендация считается ставкой в **1 условную единицу** (flat).
- Дополнительно показывается размер по ¼ Келли с потолком 2% банка — только как информация.
- Логируется всё: время, рынок, коэффициент в момент рекомендации, `p_model`, edge, флаги,
  вариант (`base` / `shadow_llm`), закрывающий коэффициент (где есть), результат.
- Расчёт результатов автоматически по итоговому счёту из API-Football.
- Метрики: ROI, hit rate, средний edge, **CLV** (для тоталов), калибровка (Brier, reliability),
  сравнение `base` и `shadow_llm`, разбивка по рынкам и лигам.

## 8. Бэктест (обязателен до запуска в работу)

- Walk-forward по 3–5 прошлым сезонам: модель переобучается по неделям только на прошлых данных.
- Калибровка вероятностей тоталов и точного счёта против реальных исходов.
- ROI на O/U 2.5 против закрывающих коэффициентов football-data.
- Подбор `xi`, `w`, порогов. Отчёт в `reports/backtest_*.md` с графиками.
- Честность: исторических коэффициентов на точный счёт нет, поэтому по нему проверяется
  только калибровка, а не ROI.

## 9. Архитектура

```
core (Python-пакет)
 ├─ ingest/      загрузчики данных, кэш, учёт квот
 ├─ model/       Dixon-Coles, матрица счетов, рынки
 ├─ value/       edge, пороги, флаги, парсер ручного ввода
 ├─ news/        поиск, LLM-извлечение, обоснования, теневая поправка
 ├─ llm/         абстракция провайдера (Gemini первым)
 ├─ tracking/    логирование, расчёт результатов, метрики
 ├─ backtest/
 └─ scheduler/   APScheduler: обновление данных, коэффициенты, новости, расчёт
api/        FastAPI поверх core
mcp/        MCP-сервер для Hermes поверх того же core
dashboard/  Streamlit (ходит в api, не в базу напрямую)
```

- Хранилище: **SQLite** + SQLAlchemy + Alembic (переход на Postgres без переписывания).
- Конфиг: `config.yaml` (лиги, пороги, параметры модели, модели LLM); секреты в `.env`.
- Python 3.12, менеджер `uv`, `ruff`, `mypy` (строгий режим для `model/` и `value/`), `pytest`.
- Развёртывание: Docker Compose на сервере, где живёт Hermes (Oracle Cloud, **ARM64** — образы
  должны собираться под arm64).

### Клиенты
- **Hermes** через MCP-инструменты: `get_value_bets(days, leagues)`, `evaluate_manual_odds(match, text)`,
  `get_match_analysis(match)`, `get_performance(period)`. Уведомления о новых value — через
  планировщик Hermes. Если окажется, что Hermes не подключает MCP, запасной вариант — skill,
  вызывающий REST API.
- **Streamlit-дашборд**: текущие value bets с флагами, форма ручного ввода, история, графики ROI/CLV,
  калибровка, base vs shadow.

## 10. Язык

- Ответы пользователю (обоснования, тексты в Hermes и дашборде): **русский**.
- Код, комментарии, коммиты, имена: английский.

## 11. Ответственная игра

Сервис только рекомендует. Никакой автоматической постановки ставок, никаких интеграций с аккаунтами
букмекеров. В дашборде виден реальный ROI, включая отрицательный.
